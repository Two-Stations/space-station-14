

## 15. Практическое руководство: Создание EUI админ-панели

Этот раздел представляет собой пошаговое руководство по созданию нового, управляемого данными окна в админ-панели на примере `AdminShuttleEui` — интерфейса для вызова эвакуационных шаттлов для нескольких станций.

### 15.1. Обзор архитектуры

Цель — создать окно, которое при открытии запрашивает у сервера список всех текущих станций и динамически создает для каждой из них строку с элементами управления (поле для ввода времени, кнопки "Вызвать" и "Отозвать").

Как и другие EUI, архитектура делится на три части:
1.  **Content.Shared**: Определяет структуры данных, передаваемые по сети.
2.  **Content.Server**: Содержит логику получения данных и команду для открытия UI.
3.  **Content.Client**: Отвечает за отображение и отправку действий пользователя.

### 15.2. Шаг 1: Общий код (`Content.Shared`)

Создаем файл `Content.Shared/Administration/AdminShuttleEui.cs`. В нем определяются все классы, которые будут передаваться между сервером и клиентом.

```csharp
// Content.Shared/Administration/AdminShuttleEui.cs

using Content.Shared.Eui;
using Robust.Shared.Serialization;

namespace Content.Shared.Administration;

// Класс состояния, который сервер отправляет клиенту.
[Serializable, NetSerializable]
public sealed class AdminShuttleEuiState : EuiStateBase
{
    public readonly List<StationInfo> Stations;

    public AdminShuttleEuiState(List<StationInfo> stations)
    {
        Stations = stations;
    }
}

// Простая структура для хранения информации о станции.
// Важно, чтобы все поля также были сериализуемы. NetEntity и string сериализуются по умолчанию.
[Serializable, NetSerializable]
public readonly record struct StationInfo(NetEntity StationId, string Name);
```
**Ключевой момент:** Все классы и структуры, передаваемые по сети, должны быть помечены атрибутами `[Serializable, NetSerializable]`.

### 15.3. Шаг 2: Логика на сервере (`Content.Server`)

#### 1. Создание команды для открытия UI

Чтобы пользователь мог открыть наш новый интерфейс, нужна консольная команда. Самый надежный способ для админ-команд — создать класс, реализующий `IConsoleCommand` и помеченный атрибутом `[AdminCommand]`. Это гарантирует, что движок автоматически обнаружит и зарегистрирует команду.

```csharp
// Content.Server/Administration/Commands/OpenAdminShuttleUiCommand.cs

using Content.Server.Administration.Eui;
using Content.Server.EUI;
using Content.Shared.Administration;
using Robust.Shared.Console;
using Robust.Shared.IoC;

namespace Content.Server.Administration.Commands
{
    [AdminCommand(AdminFlags.Host)] // <-- Критически важный атрибут для регистрации!
    public sealed class OpenAdminShuttleUiCommand : LocalizedEntityCommands
    {
        [Dependency] private readonly EuiManager _euiManager = default!;

        public override string Command => "shuttleui";

        public override void Execute(IConsoleShell shell, string argStr, string[] args)
        {
            var player = shell.Player;
            if (player == null)
            {
                shell.WriteLine(Loc.GetString("shell-cannot-run-command-from-server"));
                return;
            }

            // Создаем и открываем EUI для игрока
            var eui = new AdminShuttleEui();
            _euiManager.OpenEui(eui, player);
        }
    }
}
```

#### 2. Создание серверного EUI

Этот класс отвечает за сбор и отправку данных клиенту.

```csharp
// Content.Server/Administration/Eui/AdminShuttleEui.cs

using System.Linq;
using Content.Server.EUI;
using Content.Shared.Eui;
using Content.Shared.Administration;
using Robust.Shared.GameObjects;
using Robust.Shared.IoC;
using Content.Shared.Station.Components;

namespace Content.Server.Administration.Eui;

public sealed class AdminShuttleEui : BaseEui
{
    [Dependency] private readonly IEntityManager _entityManager = default!;

    public AdminShuttleEui()
    {
        IoCManager.InjectDependencies(this);
    }

    // Вызывается EuiManager'ом сразу после создания сессии.
    public override void Opened()
    {
        base.Opened();
        // Уведомляет EuiManager, что состояние "грязное" и его нужно отправить клиенту.
        // Без этого GetNewState() никогда не будет вызван!
        StateDirty();
    }

    // Собирает актуальное состояние для отправки клиенту.
    public override AdminShuttleEuiState GetNewState()
    {
        // Прямой запрос к EntityManager для получения всех сущностей с StationDataComponent.
        // Это более надежно, чем полагаться на внутреннее состояние какой-либо системы.
        var stations = _entityManager.EntityQuery<StationDataComponent>()
            .Select(s => new StationInfo(_entityManager.GetNetEntity(s.Owner), _entityManager.ToPrettyString(s.Owner)))
            .ToList();

        return new AdminShuttleEuiState(stations);
    }
}
```

### 15.4. Шаг 3: Интерфейс на клиенте (`Content.Client`)

#### 1. Создание клиентского EUI-контроллера

Этот класс получает состояние от сервера и управляет окном.

```csharp
// Content.Client/Administration/Eui/AdminShuttleEui.cs

using Content.Client.Administration.UI.Tabs.AdminTab;
using Content.Client.Eui;
using Content.Shared.Eui;
using Content.Shared.Administration;

namespace Content.Client.Administration.Eui;

public sealed class AdminShuttleEui : BaseEui
{
    private readonly AdminShuttleWindow _window;

    public AdminShuttleEui()
    {
        _window = new AdminShuttleWindow();
    }

    public override void Opened() => _window.OpenCentered();
    public override void Closed() => _window.Close();

    // Вызывается EuiManager'ом, когда с сервера приходит новое состояние.
    public override void HandleState(EuiStateBase state)
    {
        if (state is not AdminShuttleEuiState s)
            return;

        // Передаем данные в окно для отрисовки.
        _window.Populate(s.Stations);
    }
}
```

#### 2. Создание дочернего элемента управления (UserControl)

Чтобы не дублировать XAML, создается отдельный элемент для одной строки в списке.

**XAML:**
```xml
<!-- Content.Client/Administration/UI/Tabs/AdminTab/StationEvacControl.xaml -->
<BoxContainer xmlns="https://spacestation14.io"
              xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
              x:Class="Content.Client.Administration.UI.Tabs.AdminTab.StationEvacControl"
              xmlns:cc="clr-namespace:Content.Client.Administration.UI.CustomControls"
              Orientation="Horizontal"
              HorizontalExpand="True">
    <Label Name="StationName" MinWidth="150" />
    <LineEdit Name="ShuttleTime" Text="5:00" PlaceHolder="m:ss" MinWidth="50" />
    <cc:CommandButton Name="CallButton" Text="{Loc 'comms-console-menu-call-shuttle'}" />
    <cc:CommandButton Name="RecallButton" Text="{Loc 'comms-console-menu-recall-shuttle'}" />
</BoxContainer>
```

**C# (Code-behind):**
```csharp
// Content.Client/Administration/UI/Tabs/AdminTab/StationEvacControl.xaml.cs
using System;
using Content.Shared.Administration;
// ... другие using ...

namespace Content.Client.Administration.UI.Tabs.AdminTab
{
    [GenerateTypedNameReferences]
    public sealed partial class StationEvacControl : BoxContainer
    {
        private readonly NetEntity _stationId;

        public StationEvacControl(StationInfo station)
        {
            RobustXamlLoader.Load(this);
            _stationId = station.StationId;

            StationName.Text = station.Name;
            ShuttleTime.OnTextChanged += OnTimeChanged;
            RecallButton.Command = $"recallevac {_stationId}";

            OnTimeChanged(new LineEdit.LineEditEventArgs(ShuttleTime, ShuttleTime.Text));
        }

        private void OnTimeChanged(LineEdit.LineEditEventArgs obj)
        {
            // ... логика для валидации времени и обновления команды кнопки "Call" ...
            var timeSpanValid = TimeSpan.TryParseExact(obj.Text, ...);
            CallButton.Disabled = !timeSpanValid;
            if (timeSpanValid)
                CallButton.Command = $"callevac {obj.Text} {_stationId}";
        }
    }
}
```

#### 3. Создание главного окна

Это окно будет содержать список дочерних элементов.

**XAML:**
```xml
<!-- Content.Client/Administration/UI/Tabs/AdminTab/AdminShuttleWindow.xaml -->
<DefaultWindow xmlns="https://spacestation14.io"
            xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
            x:Class="Content.Client.Administration.UI.Tabs.AdminTab.AdminShuttleWindow"
            Title="{Loc 'admin-shuttle-title'}"
            MinWidth="500">
    <BoxContainer VerticalExpand="True">
        <ScrollContainer VerticalExpand="True">
            <BoxContainer Name="StationContainer"
                          Orientation="Vertical"
                          HorizontalExpand="True"
                          VerticalExpand="True"/>
        </ScrollContainer>
    </BoxContainer>
</DefaultWindow>
```

**C# (Code-behind):**
```csharp
// Content.Client/Administration/UI/Tabs/AdminTab/AdminShuttleWindow.xaml.cs
using System.Collections.Generic;
// ... другие using ...

namespace Content.Client.Administration.UI.Tabs.AdminTab
{
    [GenerateTypedNameReferences]
    public sealed partial class AdminShuttleWindow : DefaultWindow
    {
        public AdminShuttleWindow()
        {
            RobustXamlLoader.Load(this);
        }

        public void Populate(List<StationInfo> stations)
        {
            StationContainer.RemoveAllChildren();
            foreach (var station in stations)
            {
                var control = new StationEvacControl(station);
                StationContainer.AddChild(control);
            }
        }
    }
}
```

### 15.5. Ключевые моменты и частые ошибки

При создании EUI легко допустить ошибки, которые не вызывают явных сбоев, но приводят к тому, что UI не работает или отображается пустым.

1.  **Атрибут `[AdminCommand]`**: Команды, открывающие админские UI, должны быть помечены этим атрибутом, иначе движок их не найдет, и вы получите ошибку "Unknown command".
2.  **`Opened()` и `StateDirty()`**: Чтобы инициировать первую отправку данных от сервера к клиенту, необходимо переопределить метод `Opened()` в серверном EUI и вызвать в нем `StateDirty()`. Без этого `GetNewState()` никогда не будет вызван, и UI на клиенте останется пустым.
3.  **Исключения в конструкторе UserControl**: Если в конструкторе дочернего элемента (`StationEvacControl`) происходит исключение (например, `ArgumentNullException` при парсинге `null`-строки), элемент просто не будет создан и добавлен. При этом вся страница не "упадет", а просто останется пустой, что усложняет диагностику. Всегда проверяйте на `null` и задавайте значения по умолчанию.
4.  **Свойства `VerticalExpand` и `HorizontalExpand`**: Если контейнер, в который вы динамически добавляете элементы, не имеет свойства `VerticalExpand="True"`, его высота может остаться равной нулю, и ни один из дочерних элементов не будет виден.
5.  **`ScrollContainer` vs `ScrollViewer`**: В XAML проекта следует использовать `<ScrollContainer>`, который является частью UI-фреймворка игры, а не базовый `<ScrollViewer>` из движка.
